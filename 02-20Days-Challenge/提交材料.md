## 表单正文（已提交，998 字）

**① 最终产出**

校园WiFi信号地图（Campus-WiFi-Map），纯 HTML+CSS+JS 单页应用，零依赖，已部署 GitHub Pages，手机可直接访问。5 个模块：信号分布地图（3 栋建筑 SVG 楼层图 + 8 个测量点位）、测量点录入、数据列表筛选、热力图（Canvas + IDW 插值）、关于页；另有 TelemetryLogger 自动埋点、CSV/JSON 导出、Service Worker 离线缓存。

**② 核心实测数据**

24 组原始数据（8 点位 × 3 轮），iPhone 15 Pro + Wi-Fi Analyzer 采集：信号 -85~-43 dBm（跨度 42dBm）；延迟 8~58 ms；下载 11.0~84.7 Mbps。定位两处盲区：数据机房均值 -82.3 dBm（金属机柜遮挡）、楼梯转角 -78.0 dBm（混凝土墙），最优为 431 实训室内部 -44.0 dBm。

连续运行日志：开发者侧 7 天 381 条/12 会话，5 位同学侧 36 条/6 会话，合计 417 条（tab_switch 195、telemetry_exported 43、heatmap_rendered 34）。Git 迭代 3 次：v1.3 深色模式、v1.4 信号趋势折线图、v1.5 一键分享。

**③ 最大技术卡点**

卡点1：本地 `file://` 路径手机打不开，同学无法实测。把站点文件放入 `docs/` 并开启 GitHub Pages，得到公网地址（国内免代理）。

卡点2：`localStorage` 是设备本地的，别人手机上的日志与反馈无法自动汇总。给埋点类加"导出运行日志"按钮，序列化为 JSON 下载回传才凑齐多人数据。

卡点3：楼层图最初用 CSS 虚线框绘制，手机几乎不可见，重写为 SVG 实绘房间/墙体/门窗/指北针/比例尺。

**尚未解决的缺陷**

1. 数据是 10-22 单次静态快照，纯前端拿不到系统 WiFi 接口，无法实时探测，AP 调整后即过期。
2. IDW 在样本稀疏区会外推出并不存在的平滑渐变，热力图"看着连续"但无实测支撑。
3. 日志缺 10-27 一天（漏记）。
4. 反馈无服务端需人工回收，计划 8 份实收 5 份，下载在部分手机浏览器失败。
5. 多数用户只切 1~2 个标签就退出，工具实际价值尚未验证。

## 关于演示视频

**未提交视频，因为确实没有录制。** 现场操作视频需要真机录屏，本机未留存任何录屏文件，也没有补录。

表单若有视频要求而实际缺失，面试时的说明口径应当是：*"作品已上线，可直接用手机打开验证，比视频更有说服力；视频缺失是我这一阶段的疏漏。"* 用链接替代视频是合理的，**但不要提交任何非真实录制的演示内容**——AI 生成的假录屏在考核中属于伪造材料，被发现的代价远大于缺一项附件。

这条不是我自己的顾虑，表单步骤 5 的《学术诚信承诺》原文就写明：*"绝无使用大模型虚构伪造原始数据……愿意接受后续面试环节对代码细节与原始数据的现场溯源核验。"* 所以仓库里保留缺失日（10-27）、保留不利结论（多数用户只切 1~2 个标签就退出）是符合承诺要求的做法，而不是减分项。
