# 05 · 遥测日志跨设备汇总

## 我的提问

> 我让别人测网速，手机上日志保存到哪里？

## 问题本质

埋点用的是 `localStorage`：

```javascript
localStorage.setItem('campus_wifi_telemetry', JSON.stringify(events));
```

`localStorage` 是**浏览器沙箱内、按设备隔离**的。这意味着：

- 我自己电脑上的日志 → 只在我电脑的浏览器里
- 同学手机上的日志 → 只在他手机的浏览器里
- **没有任何办法自动汇总到我这边**

项目四要求"7 天连续运行日志"和"8 位用户反馈"，但服务端一个都没有（纯前端、零后端）。日志拿不到，要求就无法证明。

## 候选方案

| 方案 | 可行性 | 说明 |
|-----|-------|------|
| 加后端数据库收集 | ❌ | 违背"轻量化、零依赖"定位，要买服务器 |
| 用 GitHub Issue 当后端 | ⚠️ | 同学要登录 GitHub，门槛太高 |
| 导出 JSON 手动回传 | ✅ | 实现最简单，同学点一下就能导出 |

## AI 的实现

给埋点类加 `exportLogs()` 方法，按日期序列化后触发浏览器下载：

```javascript
exportLogs(date) {
    const events = this.getEvents().filter(e => e.timestamp.startsWith(date));
    const blob = new Blob([JSON.stringify(events, null, 2)], {type:'application/json'});
    const a = document.createElement('a');
    a.href = URL.createObjectURL(blob);
    a.download = `telemetry_logs_${date}.json`;
    a.click();
}
```

配套流程：同学用完 → 点"导出运行日志" → 微信把 JSON 发我 → 我放进 `process_logs/` → `git push`。

## 实际收到的东西

12 个 JSON 文件，共 417 条事件：
- 开发者侧（我自己）：7 天 381 条 / 12 会话
- 同学侧：36 条 / 6 会话，来自 4 种不同设备（Android VivoBrowser、iPhone Safari 等，从 userAgent 区分）

## 这个方案暴露的问题

**收集成本极高。** 我必须主动催每个人"记得导出并发给我"，有人导出失败、有人忘了。原计划 8 份反馈，实收 5 份。

**结论：纯前端做遥测是可行的，做数据回收是不可行的。** 下一阶段如果继续这个方向，必须加一个最小后端（或者用表单服务）才能规模化。这一点写进了提交材料的"尚未解决的缺陷 4"。
