# AI 协作记录

本目录记录阶段二开发过程中的关键 AI 协作对话与排障过程。

**先说清楚分工**（这也是本项目的一个真实特征）：

| 环节 | 谁做的 |
|------|-------|
| 24 组实测数据采集、8 个点位的选取与测试轮次设计 | **本人**（课题 03 现场完成） |
| 需求描述、问题发现、效果验收 | **本人** |
| 代码实现（HTML/CSS/JS、SVG 楼层图、IDW 热力图、埋点类、PWA） | **AI 生成** |
| 部署方案（GitHub Pages）、目录结构整理 | **AI 生成 + 本人操作** |
| 日志分析与缺陷归纳 | **AI 统计，本人确认** |

说白了，我在这个项目里的角色更接近**需求方 + 测试方**，而不是逐行写代码的人。
下面记录的每一次排障，起点都是**我在真机或网页上看到了问题**，而不是 AI 自己发现的。

## 从这些记录里能看到的、我确实学到的东西

1. **能判断"做错了"**。楼层图看不见、手机打不开、反馈收不到——这三个问题都是我先发现并描述给 AI 的，AI 给方案，我验收。这种判断力不依赖会不会写代码。

2. **知道了自己的边界**。让我从零手写 IDW 插值我写不出来，但我能看懂 `weight = 1/(dist*dist)` 是平方反比，也能判断"样本稀疏区不该画渐变"这个改进方向。

3. **踩到了真实的工程约束**。file:// 协议、localStorage 的设备隔离、GitHub 不预览 xlsx、浏览器拿不到 WiFi RSSI——这些是纸面学习碰不到的东西，只有在"想让同学真用起来"时才会撞上。
